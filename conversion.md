# Translating oMyImage into another language

The playbook for localizing oMyImage, starting with **Brazilian Portuguese
(`/pt`)**. It is adapted from oMyPDF's `conversion.md`
(`E:\omypdf-files\omypdf-project\conversion.md`), which records five shipped
locales' worth of traps. Every rule there that applies here is restated below
with its oMyPDF section number, so the reason is one click away. Everything
learned on oMyImage itself is added as it happens: **this is a living document —
append to §6 at the end of every batch.**

**Read §6 before touching a string.** Most of it is not "how to translate" — it
is the list of ways a page can look finished, pass every automated check, and
still render English.

| | |
|---|---|
| Status of every page | [`tracker.csv`](./tracker.csv) — one row per URL, regenerated by `npm run i18n:list` |
| Branch | `conversion` |
| First locale | Portuguese (Brazilian), `/pt`, `hreflang="pt"`, `og:locale=pt_BR` |
| Why Portuguese first | Analytics country split: India 13.0%, **Brazil 9.1%**, Indonesia 9.1%, Russia 6.2%, Japan 5.8%. Brazil is the largest audience that English does not serve. Indonesia, Russia and Japan are the likely next three. |
| Out of scope, by decision | `/blog` and its posts (English-only, 2026-09-19), `/admin/*`, `/auth/callback` |

## 1. The architecture in one page

Four layers. Only the last differs per language.

| Layer | Lives in | Shared across languages? |
|---|---|---|
| **Structure** — breadcrumbs, hero, related tools, SEO block, JSON-LD | `src/components/ToolPageShell.tsx` | ✅ one file, 30 hand-built tools |
| **Structure** — the 10 format converters | `src/components/ConverterPage.tsx` + `src/lib/converters/*` | ✅ one engine, 10 routes |
| **Behaviour** — the tool itself | `src/app/<slug>/<Tool>.tsx` | ✅ the `/pt` route imports the same component |
| **Copy** | `src/content/tools/<toolId>.<locale>.ts` | ❌ by necessity |

A tool route is ~15 lines:

```tsx
import { ToolPageShell } from "@/components/ToolPageShell";
import { toolMetadata } from "@/lib/i18n/tool-meta";
import content from "@/content/tools/compress-image.pt";
import { CompressTool } from "@/app/compress-image/CompressTool";

export const metadata = toolMetadata(content);

export default function Page() {
  return (
    <ToolPageShell content={content}>
      <CompressTool />
    </ToolPageShell>
  );
}
```

The English pages were moved onto this shell in Phase 0 by a codemod that read
each `page.tsx` AST, refused anything off-template, and wrote the copy to
`<id>.en.ts`. **The exported English HTML was proved unchanged** — title, meta,
canonical, JSON-LD and every visible word — by snapshotting `out/` before and
after and diffing (§6.1). Keep it that way: any change to the shell must diff
clean for English.

### Translation runtime (`src/i18n/`)

Ported from oMyPDF unchanged in behaviour:

- **Keys are the English source string.** `t("Download")` looks up
  `"Download"`. A miss falls back to the key, so an untranslated string shows
  correct English, never a blank or a dotted id. Consequence to accept:
  editing English copy silently reverts that string to English until
  re-translated — `npm run i18n:keys pt` lists them.
- `|context` suffixes disambiguate (`t("Crop|verb")`); stripped on fallback.
- `{name}` placeholders: `t("Converted {n} images to {format}.", { n, format })`.

| Scope | File | Bundled |
|---|---|---|
| Shared chrome | `src/i18n/dictionaries/pt/common.ts` | everywhere — keep it to genuinely shared strings |
| Tool names, descriptions, categories | `src/i18n/dictionaries/pt/tools.ts` | everywhere (menus list every tool) |
| Search synonyms | `src/i18n/dictionaries/pt/aliases.ts` | with the search box |
| Site tagline / home copy | `src/i18n/dictionaries/pt/site.ts` | home + `/pt` layout |
| Per tool | `ui: {}` in `src/content/tools/<id>.pt.ts` | with that route only |
| Per static page | `src/i18n/dictionaries/pt/pages/<page>.ts` | with that route only |

| Piece | File |
|---|---|
| Locales, prefixes, BCP-47 tags, `og:locale`, labels | `src/i18n/config.ts` |
| Translator (pure, server-safe) | `src/i18n/t.ts` — `getT(locale)` for server components |
| React bindings | `src/i18n/I18nScope.tsx` — `useT()`, `useLocale()`, `useFormatBytes()` |
| Number/date/byte formatting | `src/i18n/format.ts` |
| Translatable errors | `src/i18n/errors.ts` — `I18nError`, `translateError()` |
| Tool slugs per locale | `src/i18n/slugs.ts` |
| Static-page paths per locale | `src/i18n/static-paths.ts` |
| **Rollout gate** | `src/i18n/status.ts` — `SHIPPED_TOOLS`, `SHIPPED_PAGES` |
| Locale-aware links | `src/lib/i18n/links.ts` — `toolHref`, `localeHref`, `localeHome`, `swapLocale` |
| Metadata + hreflang | `src/lib/i18n/tool-meta.ts` — `toolMetadata`, `pageMetadata` |
| Tool labels in lists | `src/lib/i18n/tool-labels.ts` — `toolName`, `toolDescription`, `categoryNavLabel` |
| `<html lang>` | pre-paint stamp in `NO_FLASH_THEME` (`app/layout.tsx`) + `components/HtmlLang.tsx` |
| Language menus | `src/lib/languages.ts` — `available` is **derived** from `status.ts` |

### Rollout behaviour (oMyPDF §8)

- `toolHref` / `localeHref` are gated on `status.ts`. A tool not yet shipped in
  Portuguese links to its **English** page from a Portuguese page. During
  rollout a `/pt` page legitimately mixes `/pt/…` and `/…` links — the gate
  working, not a bug. Each link flips the moment its tool ships.
- `swapLocale` sends a visitor with no counterpart to the locale **home**, never
  back to the page they are on. Until `/` itself ships in Portuguese,
  `localeHome("pt")` is `/`, and Português stays "Em breve" in the language
  menus — `lib/languages.ts` derives `available` from `pageShippedIn("/", code)`.
- hreflang is emitted only once 2+ locales have the page, and it is
  **reciprocal**: the English page starts advertising the Portuguese one in the
  same build that ships it. `x-default` is English.
- English pages never got `og:locale` or JSON-LD `inLanguage`; those are
  emitted on translated pages only, to keep English byte-identical.

## 2. Starting a new language (after Portuguese)

Do these once, before any page. Every one of them fails **silently** if missed —
the page just renders English.

1. `src/i18n/config.ts` — add the code to `LOCALES` and a row to
   `LOCALE_PREFIX`, `LOCALE_TAG`, `OG_LOCALE`, `LOCALE_LABEL`. Use the
   language-only tag (`id`, `ru`, `ja`) unless you publish two variants.
2. `src/i18n/slugs.ts` — `<XX>_TOOL_SLUGS` for **all 40 tools**, as an
   authored object literal (a derived `Object.fromEntries(...)` map breaks the
   text parsers — oMyPDF §4.28). Wire it into `TOOL_SLUGS`. §5 for how to pick.
3. `src/i18n/static-paths.ts` — `<XX>_PATHS`.
4. `src/i18n/status.ts` — empty arrays in **both** gates.
5. `src/i18n/dictionaries/<xx>/` — `common.ts`, `tools.ts`, `aliases.ts`, `site.ts`.
6. Register the dictionaries: `COMMON` in `src/i18n/t.ts`, `DICTS` and
   `CATEGORY_DICTS` in `src/lib/i18n/tool-labels.ts`, `LOCALE_ALIASES` in
   `src/lib/tool-search.ts`.
7. `src/app/<xx>/layout.tsx` — copy `app/pt/layout.tsx`.
8. `app/layout.tsx` — add the code to the `L={pt:1}` map in `NO_FLASH_THEME`.
9. `src/lib/languages.ts` — the row already exists for id/ru/ja/hi/es/fr/de; it
   flips to available by itself when `/` ships.
10. `scripts/i18n-hardcoded.mjs` — add the prefix to `SKIP_DIR` (the localized
    routes contain localized literals on purpose). `i18n-verify.mjs` — add the
    `OG` row.
11. Script needs a font? Inter's `latin` subset covers Portuguese and
    Indonesian; **Russian needs `cyrillic`, Japanese needs a CJK face** — decide
    before the first page, and scope it with `:lang(xx)` so other locales don't
    pay for it (oMyPDF did this for Devanagari).

Then `npm run i18n:audit` — it checks slugs (ASCII, unique, no collision with a
static path) and that every gate entry has its route and module.

## 3. Per-page procedure

### (a) A hand-built tool

1. **Read the component fully** — including early returns, sub-components and
   the mobile branch (§6.3). `grep -n "^function\|^export function"` first:
   every sub-component needs its own `const t = useT();`.
2. `npm run i18n:props -- src/app/<slug>` lists every unwrapped literal. Wrap
   them. Plurals are two keys; counts go inside the phrase (§6.4).
3. `formatBytes` → `const formatBytes = useFormatBytes();` next to `useT()`.
4. `npm run i18n:keys pt <slug>` → write `src/content/tools/<id>.pt.ts`,
   copying the shape of `<id>.en.ts`. Its `ui` block holds that tool's keys.
5. Route: `src/app/pt/<pt-slug>/page.tsx` (§1).
6. Add the id to `SHIPPED_TOOLS.pt` **in the same commit**.

### (b) A converter (the 10 data-driven pairs)

Copy lives in `lib/converters/` (`pairs.ts` `unique` blocks, `copy.ts`
generated steps/features/FAQs, `formats.ts` essays), not in content modules.
The Portuguese layer is added in batch 7; `ConverterPage` already takes
`locale`. The 900-word floor **and** the 0.6 similarity ceiling apply to the
Portuguese converters too — generated boilerplate translated once is exactly
what makes ten pages near-duplicates.

### (c) Static pages (contact, pricing, legal, auth)

A page dictionary `src/i18n/dictionaries/pt/pages/<page>.ts` loaded with that
route through `<I18nScope locale="pt" dict={…}>`, plus `pageMetadata()`.
Legal pages pass `locale` to `LegalShell` (server component). Auth pages ship
`robots: noindex`; check that post-login redirects and the cross-links
("Esqueceu a senha?") stay under `/pt` (oMyPDF §3d).

### (d) The home page

`/pt` renders the same `HomeLauncher` + `ToolDirectory`, with the H1, intro
and meta from `dictionaries/pt/site.ts` — written for the Brazilian SERP, not
translated from the English brand line (§5).

## 4. The batch-of-five loop

Five pages per batch, in the order in `tracker.csv` (Brazilian search value
first). oMyPDF measured the rhythm: small batches done directly beat large
parallel ones, which died mid-edit and left the tree unbuildable (its §7).

1. Re-check the five head terms (§5): the competitors' `/pt` page plus a SERP.
   A slug is free to change until it ships; after that it is permanent.
2. Sweep + content modules + routes + `status.ts` (§3).
3. Gates, in this order:
   ```bash
   npx tsc --noEmit --incremental false
   npm run i18n:keys pt
   npm run i18n:audit
   npm run i18n:verify -- pt <slug>,<slug>,<slug>,<slug>,<slug>
   ```
   `i18n:verify` needs the dev server on :3002. It must read **5/5 clean**;
   read its `title` and `h1` lines, not just the ✓.
4. **Browser QA** at desktop and at phone width: upload a real image, run the
   tool, and read the result screen. Check `document.documentElement.lang`.
   Every English survivor oMyPDF found after its gates went green was behind an
   upload, a modal, the result screen or the narrow-viewport branch (its §6).
5. `npm run i18n:list`, fill the hand-set columns of the five rows, append what
   the batch taught to §6 below, commit.

Before handing off (not per batch): stop the dev server, `npm run build`,
`npm run verify:build`, diff English against the snapshot, restart the server.
**Never `rm -rf .next` or build while `next dev` is running** — it destroys the
live server's manifests (every request 500s).

## 5. Copy and SEO conventions — Portuguese (Brazilian)

### What the market does (checked 2026-09-19, not recalled)

| Site | Prefix | Variant | Evidence |
|---|---|---|---|
| iLoveIMG | `/pt` | **mixed** | Brazilian "você", but "Carregue seu **ficheiro**" (European) on `/pt/comprimir-imagem` and `/pt/remover-fundo`; `/pt/rodar-imagem`, `/pt/desfocar-cara` (European forms). ~350–450 words per page, no FAQ. |
| imagetotext.info | `/br` | Brazilian, mostly | `/br/imagem-em-texto`, H1 "Converter Imagem em Texto", ~2,800 words, 4 FAQs — "arquivo" and "ficheiro" both appear |
| Adobe Express | `/br` | Brazilian | "Transforme imagens PNG para JPG"; "baixar o arquivo" |
| Smallpdf | `/pt` | Brazilian | `png para jpg` guides, "arquivos", "você" |

Two conclusions. iLoveIMG's mixing of European forms into Brazilian copy is
the thing to beat, not copy — the same finding oMyPDF made about iLovePDF. And
iLoveIMG's Portuguese pages are **thin** (a tool and a sentence); the 900-word
floor with real long-tail sections is how oMyImage outranks them.

### URL, tags, register

- **One `/pt`, `hreflang="pt"`, `og:locale=pt_BR`, 🇧🇷.** A region subtag is
  only needed with two variants; the bare tag also serves PT/AO/MZ.
- **"Você"** with imperatives: "Selecione", "Comprima", "Baixe".
- **Gender:** *a imagem*, *a foto* (feminine); formats are masculine — *o PNG,
  o JPG, o PDF, o GIF*, plural bare `-s` (*os PNGs*), never an apostrophe.

### Pinned vocabulary

| Use | Not | Note |
|---|---|---|
| arquivo | ficheiro | the one iLoveIMG gets wrong |
| baixar | descarregar | button: "Baixar" |
| excluir / remover | eliminar / apagar | "remover fundo" is the head term |
| senha | palavra-passe | |
| tela | ecrã | |
| celular | telemóvel | |
| girar | rodar | slug `girar-imagem` |
| rosto | cara | slug `desfocar-rosto` |
| foto / imagem | fotografia | "foto" in casual copy, "imagem" in tool names |
| contato | contacto | |
| grátis | gratuito | both correct; "grátis" is what gets typed |

European forms go in `dictionaries/pt/aliases.ts`, where they catch the query
without making the interface inconsistent.

### Slugs

`x-para-y` for conversions (`png-para-jpg`, `imagem-para-pdf`) — iLoveIMG,
Adobe BR and Smallpdf all use it. Lowercase ASCII, hyphenated (`marca-dagua`,
not `marca-d'água`). The full map is `src/i18n/slugs.ts`; each is re-checked at
the start of its batch and **frozen once shipped**.

### The copy is not a translation (oMyPDF §5)

- The head term goes in `metaTitle`, the H1 (`name`), the **first sentence** of
  `intro`, and `howToTitle`.
- `metaTitle` pattern: `<Head term> online grátis — <benefit> | oMyImage`,
  ≤ 60 characters where possible. `metaDescription` ≤ 155, ends on the
  objections that decide the click (sem cadastro, sem marca d'água, no
  navegador).
- 2–4 `sections` written against real Brazilian long-tail queries, with the
  English section **ids** kept (the audit checks them).
- **AEO:** FAQs phrased the way people type ("É grátis?", "Minhas fotos ficam
  salvas?", "Funciona no celular?"), first sentence of each answer a complete
  standalone answer.
- Steps quote the **translated** button labels — "Clique em **Comprimir**", not
  "Clique em Compress" (oMyPDF §4.24).
- A market-specific FAQ the English page lacks is fine (WhatsApp image limits,
  documents for gov.br uploads) — never claim a compliance we can't verify.

### Never translate

Format names (JPG, PNG, WEBP, HEIC, AVIF, GIF, BMP, JFIF, PDF, SVG, Base64),
EXIF/GPS/OCR, product and plan names (Free / Plus / Pro — checkout keys on
them), brand names (Google Drive, Dropbox, WhatsApp, Trustpilot), keyboard
keys (Ctrl — Brazilian keyboards label it Ctrl). Mark genuinely identical
values `// i18n-same`.

## 6. The traps

### 6.1 Carried over from oMyPDF — read the original section for the story

| oMyPDF § | Trap | oMyImage status |
|---|---|---|
| 4.1 | `t()` is per-component; early-return and mobile branches hide strings | Every sub-component needs its own `useT()`. `i18n:props` flags them. |
| 4.2 | Module-scope config arrays are invisible to the key extractor | Wrap at the render site (`{t(o.label)}`), add keys by hand with a comment. Found in Phase 0: nav sections, footer columns, cookie categories, background swatches, effect names, crop ratios. |
| 4.3 | Feature icons must be byte-identical to English | Asserted by `i18n:audit`. The icon font is a subset (`build-icon-font --check`). |
| 4.4 / 4.20 | Plurals are two keys; a count glued to a noun is a phrase | `filesHeader`, ConvertTool, cloud import already split. |
| 4.5 | Never interpolate before translating | Use placeholders; lib errors use `I18nError` (§6.2). |
| 4.6 | Never translate the same string twice | ResultScreen translates only its *defaults*; callers pass `t("…")`. |
| 4.7 | React keys must stay locale-independent | `key={x.id}`, never `key={t(x)}`. |
| 4.8 | HTML entities don't survive leaving JSX | `&amp;` → `&` when moving copy into a module. The codemod decoded them. |
| 4.10 | Server components take `locale`, use `getT()` | SeoContent, Breadcrumbs, RelatedTools, LegalShell, ToolPageShell. |
| 4.11 | A shared component can only read `common.ts` | `i18n:keys` buckets by who renders a key. |
| 4.12 | `loading:` callbacks run at module scope | Grep `loading:` when sweeping a tool with `dynamic()`. |
| 4.13 | `ResultScreen` does not translate its props | Same here, by design. |
| 4.16 / 4.32 | `toLocaleString()` follows the browser; path-derived locale is empty during prerender | `format.ts` + `useFormatBytes()`. `formatBytes` has ~25 call sites — each tool's sweep moves it onto the hook. |
| 4.18 | Template-literal labels, and a map variable that shadows `t` | Found and fixed in ResultScreen (`handoffTargets.map((t) => …)`) and ToolWorkspace (`tabs.find((t) => …)`). Grep `((t)` / `(t) =>` in every tool. |
| 4.21 | A branch editing `page.tsx` walks past the content modules | Tool copy now lives in `content/tools/`; a `main` change to a `page.tsx` must be ported into the module. |
| 4.22 | `metaTitle`/`metaDescription` exist only in translated modules | `i18n:audit` requires them; `verify:build` checks `<title>` against them. |
| 4.23 | Copying a German `ui` block imports `„…"` | `i18n:audit` fails on `„`. |
| 4.24 | Steps name a button the page doesn't have | Quote the translated label. |
| 4.25 / 4.27 / 4.30 | A string that never reaches `t()` is not a missing key | Answered here by an **AST** scanner (§7), not three regexes. |
| 4.26 | Two spellings of one sentence are two keys | Collapsed "No tools match" (header had `&quot;`, drawer had `“”`) to one key. |
| 4.28 / 4.35 | A text parser bounded only at its start runs into the next locale | Every script's `block()` is bounded at both ends. |
| 4.29 | A regex comment-stripper eats `accept="image/*"` | `i18n-keys.mjs` anchors block comments to line start — oMyImage has `image/*` in dozens of files. |
| 4.31 | Locale-blind path guards switch features off | Nothing records visits today; `canonicalToolSlug()` in `links.ts` exists for when something does. `useRequireAuth` now redirects to the localized login. |
| 4.36 | The word floor never looked at a translated page | `verify-build.mjs` checks `out/pt/*.html`: floor, title, canonical, hreflang, JSON-LD, duplicate FAQs, converter similarity, sitemap. |
| §2 step 7 | `<html lang>` is wiped by React on any hydration mismatch | `NO_FLASH_THEME` stamps it pre-paint; `HtmlLang` re-stamps after commit and on navigation. Diagnose with `document.documentElement.lang`, never the HTML. |
| §6 | **Heredocs eat backslashes** | Hit three times in Phase 0 (a `\b` became a backspace byte; `\u0300` became raw combining marks; a script edit had to be reverted). Anything with a regex or escape goes through the Edit tool. |

### 6.2 Found on oMyImage

**The English pages were not on a shell.** oMyPDF's i18n started after its
pages were templated; oMyImage's 30 tool pages were 145-line files of inline
copy. A codemod moved them, and the proof is the snapshot diff: extract title,
metas, canonical/alternates, parsed JSON-LD and visible text from every
`out/*.html` before and after, diff. It caught the one page the codemod had
flattened wrong (heic-to-png's "Want a smaller file instead?" line, now the
`crossLink` field). Scripts: `scratchpad/snapshot.mjs` / `snapdiff.mjs` — copy
them into `scripts/` if they are needed again.

**Footer and Navbar sit in the root layout, which cannot see the URL.** Both
became client components reading the locale from the pathname. They still
prerender into the static HTML, so English output did not change.

**`filesHeader()` is a plain function called from 24 tools** — it cannot call
`useT()`. It now returns small elements (`<FilesCount>`, `<FilesSize>`) that
translate themselves; `ToolMobileShell.title` became a `ReactNode`.

**Errors from `lib/` reach toasts as English `err.message`.** `src/i18n/errors.ts`:
fixed-sentence errors resolve through `t(err.message)` (their English text is
the key, listed in `common.ts`); messages with a variable part throw
`I18nError(key, vars)`. Every `toast.error(err.message)` becomes
`toast.error(translateError(err, t, "Fallback."))`. The backend's own
user-facing sentences are in `common.ts` too; ops-only ones ("npm i
puppeteer") are deliberately left English.

**Search deleted accented letters.** `tool-search.ts` folded with
`[^a-z0-9]`, which turned "câmera" into "c mera". It now strips accents (NFD)
first, and scores the Portuguese name and aliases ahead of the English ones.

### 6.2.1 Batch 1 (home, comprimir, redimensionar, remover-fundo, imagem-em-texto)

**Third-party components carry their own English.** Sonner renders
`aria-label="Close toast"` on every toast's close button and "Notifications"
on its region. Neither is a literal in our source, so neither scan can see it —
it surfaced only when the DOM of a Portuguese result screen was read back after
a real run. Both are props (`toastOptions.closeButtonAriaLabel`,
`containerAriaLabel`) set in `ThemedToaster`. **Every batch: read the DOM after
an upload, including the toast.**

**One English word can be two Portuguese words.** The home "How it works" step
"Download" is an imperative ("Baixe"); the common button "Download" is
"Baixar". A page dictionary layered over `common.ts` would have made every
Download button inside the home scope read "Baixe". The step uses
`t("Download|step")` — the context suffix is stripped for English.

**Page-owned components.** HomeLauncher and ToolDirectory live in
`components/` but render only on the home page, so their keys ride with
`pages/home.ts` (HomeShell wraps them in `<I18nScope dict={ptHome}>`), and
`i18n-keys.mjs` knows it through its `PAGE_OWNED` map. Add to that map rather
than to `common.ts` for any future single-page component.

**Mixed markup is split at the markup, and each fragment must read on its own
in the target language.** "…requests the `drive.file` scope. That scope…"
rendered "…solicita o escopo drive.file . Esse escopo…" (the JSX space before
the fragment). The Portuguese fragments were rephrased around the code token
("…solicita a permissão drive.file — um escopo que…"). Check rendered text, not
the dictionary, for every split sentence.

**The translation must describe what the tool does now, not what the English
says.** `image-to-text.en.ts` still claims recognition runs in the browser and
the image is never uploaded; the tool has since become server-first (PaddleOCR)
with a Tesseract fallback. The Portuguese page describes the real behaviour.
The English page needs its own fix (tracked separately) — a translator who
copies a false privacy claim into a second language doubles it.

**OCR language follows the page.** `/pt/imagem-em-texto` defaults to `por`;
verified by reading "Ação de graças é ótima" back with every accent intact.

**Slug corrected before shipping.** `imagem-para-texto` → `imagem-em-texto`:
the Brazilian SERP says "converter imagem **em** texto" (invertexto, QuillBot,
imagetotext.info `/br/imagem-em-texto`). This is exactly why §4 step 1
re-checks head terms at the start of each batch.

**Git Bash rewrites a leading `/` argument into a Windows path.**
`npm run i18n:list -- --done "/"` marked nothing, because MSYS turned `/` into
`C:/Program Files/Git/`. Use `MSYS_NO_PATHCONV=1` for any argument that is a
URL path.

**Browser QA snippet.** A TreeWalker over visible text plus
`aria-label`/`title`/`placeholder`/`alt` and `<option>` text, flagging strings
with ≥2 English function words or a known UI verb; the file is fed with a
canvas-generated `File` through `DataTransfer` on the drop zone's input. Expect
false positives on Portuguese words sharing an English stem ("Compressão"),
on "Post"/"Stories"/"Reels" (Brazilian usage) and on the brand wordmark.

### 6.2.2 Batch 2 (recortar, png-para-jpg, jpg-para-png, converter-para-jpg, imagem-para-pdf)

**One English word, two meanings, one key — the collision is silent.**
`common.ts` translated "Legal" as "Jurídico" for the LegalShell eyebrow, and the
image-to-PDF paper-size menu then offered **"Jurídico"** as a paper format,
because a tool's `t("Legal")` falls through to `common.ts`. No gate can see it:
the key exists and is translated, just for the other meaning. Found by reading
`<option>` text in the browser. Fix: the generic meaning takes a context
(`t("Legal|section")`), so the bare key stays free for the literal one. **Any
short English word in `common.ts` is a collision candidate** (Auto, Original,
Free, Cover, Fit, Scale, Legal…). When a tool needs a different sense, override
it in the tool's `ui` block — the scope wins — as image-to-pdf does for the
orientation "Auto" → "Automática" (feminine; the background picker's is
"Automático").

**Labels derived from ids, again (oMyPDF §4.18).** Image-to-PDF's fit buttons
rendered `{f}` — the mode id "contain" — capitalised by CSS. No string exists
to scan for. They now render `t(FIT_LABELS[f])`. When a row of buttons has no
visible label string in the source, look for this.

**Strings passed as data to a shared component.** The three ConvertTool pages
pass `dropHint: "or drop PNG images here"` in a config object. ConvertTool now
translates `t(config.dropHint)` and `t(config.privacyNote)`, so the English
page files keep English source strings (marked `i18n-raw`) and each tool's
`ui` block carries the key by hand.

**`translateError(err, t, "Fallback.")` hid its key from the extractor**, which
only matched `t("…")`. The regex now also takes the third argument of
`translateError(…, t, "…")`.

**Parallel sessions share the working tree.** A spawned task (fixing the
English image-to-text copy) ran `npm run build` in this same directory
mid-batch; that killed the dev server this batch was testing against and
rewrote `.next`. Only one session may build or serve `frontimg/` at a time;
check `git status` before committing and stage paths explicitly so another
session's in-progress files do not ride along.

### 6.2.3 Batch 3 (melhorar-qualidade, editor-de-fotos, colocar-marca-dagua, girar, heic-para-jpg)

**Number labels are not names.** The watermark position grid (in two tools)
announced "Position 1"…"Position 9" — translatable, and useless to a screen
reader in any language. Both now use nine named keys ("Top left" → "Superior
esquerda"), one per cell, since a placeholder cannot build a position phrase
in another language (oMyPDF §4.18's `anchorLabels` pattern). English
screen-reader output changed with it, for the better.

**Default text drawn into the image follows the page.** The editor's annotate
stamp defaulted to "Label"; it is now `t("Label")` → "Legenda", initialised
through a `useState(() => …)` so `t` is in scope. The watermark default stays
"© oMyImage" in every language — it is the brand, not copy.

**Map variables named `t` again** in both watermark type toggles and the
editor's ribbon (`.map((t) => …)`). Renamed to `wt` before `useT()` could be
added. Grep every tool for `((t)` and `(t) =>` before sweeping.

**English-side inaccuracies found while translating** (Portuguese follows the
code, English still needs fixing):
- `heic-to-jpg.en.ts` FAQ says EXIF (date, GPS) is not carried into the
  output; `HeicTool.tsx` documents that ImageMagick copies it across and
  offers a "Strip metadata" checkbox to remove it.
- `image-to-text.en.ts` said the image is never uploaded (being fixed by a
  separate task at the time of writing).

**Shared tool components need their keys in every route that renders them.**
`HeicTool` lives in `app/heic-to-jpg/` and also renders on `/heic-to-png`. Each
route has only its own tool's `ui` in scope, so the HeicTool keys in
`heic-to-jpg.pt.ts` must be copied into `heic-to-png.pt.ts` when it ships
(batch 7). `i18n:keys` buckets by folder and cannot see this.

### 6.3 Image-specific traps (watch for these in every batch)

- **Text drawn INTO the image.** Meme captions, watermark defaults, the
  image-to-PDF page labels, anything rendered on a canvas or into a file. No
  static check sees a pixel. Default watermark text translates ("CONFIDENCIAL"),
  a user's own text never does. Generate one and look at it (oMyPDF §6's
  invoice recipe is the model).
- **OCR language.** image-to-text's default recognition language should be
  Portuguese on `/pt` (`por`) — accents are lost with an English model.
- **Download filenames.** `omyimage_result.zip`, `-compressed`, `-resized`
  suffixes: decide once per locale and record it here. (Proposal: keep the
  ASCII English suffixes — filenames travel between systems, and the brand
  prefix already identifies them. Revisit if Brazilian users say otherwise.)
- **Canvas `aria-label`s.** The interactive canvases (crop, merge, redact) speak
  only through their `aria-label` — already swept in the shared components;
  tool-local canvases are swept per batch.
- **Server-backed tools** (remove-background, upscale, heic, html-to-image, OCR
  fallback) surface backend sentences — see §6.2.

## 7. Tooling

| Command | What it does |
|---|---|
| `npm run i18n:keys pt [bucket…]` | Every `t("…")` key Portuguese lacks, bucketed by **who renders it**: `shared` → `common.ts`, a tool folder → that tool's `ui` block, a page folder → its page dictionary. "0 missing" is a claim about what it parsed — it cannot see a literal that never reached `t()`. |
| `npm run i18n:props [paths]` | **AST** scan for copy that bypasses `t()`: JSX text in any position, text-bearing props, literals inside prop and child expressions, template literals, text keys in object literals built inside components, toast messages. With no paths it is the gate: shared components + every shipped tool/page folder. `i18n-raw` comment with a reason opts a line out. `--summary` gives counts. Shared components not yet swept sit in its `PENDING` list, which must shrink to empty. |
| `npm run i18n:audit` | Slugs (ASCII, unique, no static-path collision); `status.ts` ↔ routes ↔ content modules in both directions; translated modules carry `metaTitle`/`metaDescription`/`tagline`, English icons in order, ≥ English FAQ count, every English section id; no `„`; no European vocabulary; `ui` values still equal to their key are warned. Then runs `i18n:props`. **Gates `prebuild`.** |
| `npm run i18n:verify -- pt <slugs\|--all>` | Reads the **rendered** pages (dev server, or `OUT=out`): canonical, reciprocal hreflang incl. `x-default`, `og:locale`, JSON-LD types + `inLanguage`, title/H1 differ from English, 900-word floor, and lists English-looking sentences. |
| `npm run i18n:list` | Regenerates `../tracker.csv`: URLs and the derived columns from disk, hand-set columns preserved. `-- --check` fails if stale. |
| `npm run verify:build` | After `npm run build`: English **and** shipped Portuguese pages — one H1, title, canonical, hreflang, JSON-LD, duplicate FAQs, 900 words, converter similarity (accent-folded), sitemap both ways. |
| `npx tsc --noEmit --incremental false` | Must be 0. |
